# ADR 0001: البنية المعمارية

- **الحالة:** Proposed (يُقرر نهاية السبرنت 0، 2026-12-10)
- **التاريخ:** 2026-11-15

## السياق

مُفرِّغ يخدم فرقًا تفرّغ صوتيات عربية فيها آيات وأحاديث. المتطلبات الحاكمة: دقة دينية صارمة، محرر ثقيل في المتصفح (موجة صوتية، اختصارات، عمل دون اتصال)، معالجة صوت طويلة في الخلفية، تصدير Word/PDF بتنسيق RTL دقيق، وتفريغ آلي قابل للاستبدال. الفريق يتقن Laravel وVue، ومكتبات معالجة النص العربي وASR أقوى في Python.

## القرار

| الطبقة | الخيار |
|---|---|
| الواجهة | Vue 3 + TypeScript + Vite + Pinia (SPA، RTL) |
| API | Laravel 11 (REST، Sanctum) |
| قاعدة البيانات | PostgreSQL 16 |
| الطوابير والكاش | Redis 7 (طوابير Laravel) |
| تخزين الصوت | تخزين كائني متوافق مع S3 (MinIO محليًا) |
| text-engine | خدمة Python: التطبيع، بحث القرآن/الحديث، التحقق من الكتل المقفلة، تصدير Word/PDF/SRT |
| ASR | خدمة Python منفصلة خلف واجهة موحدة؛ المحرك قابل للاستبدال |

Laravel هو المصدر الوحيد للحقيقة للبيانات والصلاحيات، ويستدعي الخدمتين عبر HTTP داخلي. العقد المشترك للمستند في `shared/schemas/document.schema.json`.

## النتائج

- (+) فصل منطق الدقة الدينية في وحدة واحدة قابلة للاختبار باستقلال عن الواجهة.
- (+) استبدال محرك ASR دون المساس ببقية النظام.
- (+) التوسع الأفقي للمعالجة الثقيلة عبر الطوابير.
- (-) ثلاث بيئات تشغيل (PHP, Node, Python): تعقيد في النشر وCI.
- (-) اتصالات بين الخدمات تحتاج مهلات وإعادة محاولة ومراقبة.
- (-) تصدير Word/PDF في Python يتطلب خطوطًا (خط مصحف) مثبتة في الحاوية.

## البدائل المدروسة

1. **Laravel monolith بالكامل (Blade/Livewire):** أبسط نشرًا، لكن المحرر التفاعلي والمشغل الصوتي أصعب، ومكتبات النص العربي/ASR أضعف في PHP.
2. **Node/NestJS بدل Laravel:** لا ميزة تعويضية مع خبرة الفريق في Laravel.
3. **Python (FastAPI/Django) للـ API كله:** يلغي خدمة وسيطة، لكن يخالف خبرة الفريق ويبطئ بناء CRUD والأدوار.
4. **ASR سحابي (API خارجي) فقط:** سريع البدء، لكنه يربط الخصوصية والتكلفة بمزوّد؛ يبقى خيارًا خلف الواجهة القابلة للاستبدال، ويحسمه benchmark السبرنت 0.
